# ОГОРОД — игровой движок на C

Настоящий движок, выросший прямо из репозитория PvG3: он переиспользует
оригинальные рисунки автора (`assets/art/*.png`, упакованные в
`src/sprites_data.h`) и встроенный шрифт PT Sans (`src/font.c`), но всё
остальное — сцены, узлы, ввод, рендер и **язык ОгScript** — здесь новое.

Ни одной строки на JavaScript, HTML или Python в самом движке: только C11,
`gcc` и `make`.

```
engine/                 исходники движка
  og_common.[ch]        значения ОгScript (nil/bool/число/строка/массив/узел)
                        и подсчёт ссылок
  og_vm.[ch]            лексер, компилятор в байткод, стековая ВМ
  og_node.[ch]          узлы сцены: спрайт, надпись, прямоугольник, круг
  og_image.[ch]         распаковка спрайтов автора, примитивы, BMP
  og_runtime.[ch]       главный цикл, жизненный цикл узлов, ввод, повтор
  og_bind.c             встроенные функции и свойства для сценариев
  og_scene.c            project.cfg и сцены
  og_main.c             консольный запускатор `ogorod`
  tests/                vm_test, engine_test, demo_test
projects/
  oborona/            «Оборона грядки» — башенная оборона на ОгScript
  kirpichi/           «Кирпичи» — арканоид на ОгScript
```

## Сборка и запуск

```sh
make -C engine            # -> engine/ogorod
engine/ogorod run projects/oborona --frames 3000 \
        --shot 120=start.bmp --shot 1400=battle.bmp
engine/ogorod run projects/kirpichi --frames 4000 --shot 1200=game.bmp
make -C engine test       # 106 проверок + два авто-матча демо-игр
```

## Команды `ogorod`

| Команда | Что делает |
|---|---|
| `ogorod run <проект>` | симулирует проект детерминированно |
| `--frames N` | сколько кадров (по умолчанию 10 секунд) |
| `--input файл` | повтор ввода: `кадр press\|move\|release x y` |
| `--shot КАДР=файл.bmp` | скриншот указанного кадра |
| `--every N --shots-dir каталог` | кадры через каждые N (для гифок) |
| `--scale S` | уменьшить снимок в S раз |
| `--headless` | считать, ничего не рисуя |
| `ogorod check сценарий.og` | только компиляция сценария |
| `ogorod tree <проект>` | распечатать дерево сцены |

## Проект и сцены

`project.cfg` — настройки проекта:

```
name = Оборона грядки
main_scene = scenes/main.scene
width = 1280 / height = 720 / fps = 60 / seed = 20260930 / bg = #20242b
```

Сцена — секции `[node]` со свойствами `ключ = значение`. Первый узел файла
становится корнем, у остальных указан `parent` (путь от корня). Узлы с
`script = ...` получают свой экземпляр сценария: **у каждого узла свои
переменные**, а начальные значения задаются ключами `var_имя`.

```
[node]
name = Утка              # имя узла (пути строятся по нему)
parent = Root            # путь родителя; первый узел — корень
type = Sprite            # Node2D (по умолчанию) | Sprite | Label | Rect | Circle
sprite = duck            # имя картинки из реестра
x = 200 / y = 60         # позиция относительно родителя
w = 90 / h = 90          # размер отрисовки (0 = родной)
sx = 0 / sy = 0 / sw = 250 / sh = 500   # исходный кусок картинки
alpha = 1.0 / flip = false / z = 0      # прозрачность, отражение, слой
text = Монеты: 0 / size = 3 / color = #ffffff / center = false
script = scripts/duck.og
var_скорость = 60        # стартовое значение переменной сценария
```

## Язык ОгScript

Отступы вместо скобок, как в Python и GDScript. Имена (переменных,
функций, узлов) можно писать кириллицей.

```og
var hp = 100                    # переменная узла
var счётчик = 0

func _ready():                  # вызывается один раз при старте
    hp = 100

func _process(dt):              # каждый кадр
    счётчик += 1
    if счётчик > 10 and hp < 50:
        self.alpha = 0.5
    elif счётчик == 10:
        hp = 50
    else:
        pass

func урон(на сколько):         # функция с параметром
    hp = hp - на сколько
    return hp

func сумма():
    var total = 0
    for к in range(5):          # for только для range(a[, b])
        total += к
    while total > 0:
        total -= 10
        if total == 40:
            break
    return total
```

Операторы: `+ - * / %`, сравнения `< <= > >= == !=`, `and or not`,
присваивания `= += -= *= /=`, составные через свойства и индексы
(`self.x += 5`, `список[0] = 7`).

Цвета пишутся прямо в сценарии: `self.fill = #d95555` (то же, что
`#RRGGBB` в файле сцен). Строку можно продолжить, если она кончается
оператором, запятой, `and`/`or` или открытой скобкой:

```og
    if ball.vy > 0 and ball.y + ball.rw > pad.y and
       ball.x > pad.x - 10 and ball.x < pad.x + pad.rw + 10:
        play_sound("удар")
```

**Хуки узла** (движок вызывает их сам):

| Хук | Когда | Смысл |
|---|---|---|
| `_ready()` | один раз, снизу вверх по дереву | инициализация |
| `_process(dt)` | каждый кадр | логика |
| `_press(x, y)` | нажатие; вернуть `true`, чтобы захватить узел | ввод |
| `_move(x, y)` | движение при захваченном нажатии | перетаскивание |
| `_release(x, y)` | отпускание | завершение |

Клон префаба сохраняет имя прототипа, поэтому несколько копий отличаются
только ссылкой на узел, а не именем — ищи их через контейнер, а не по пути.
Например: `var d = spawn("DuckProto")` и `duck.x = 400`.

**Свойства узла**: `x y z visible dead alpha w h sx sy sw sh flip sprite
text size color center rw rh fill outline`, а также любые `var` этого
узла — их видно как `узел.имя`. Методы: `free()`, `dup()` и любая функция
его сценария (`утка.побежала()`).

**Встроенные функции**: `print str num len abs floor ceil round min max
clamp sqrt rand randi time quit get_node has_node child_count get_child
spawn free_node overlaps point_in push play_sound dist`.

Массивы: `[1, 2, 3]`, `len(массив)`, `a.push(x)`, `a.pop()`, `a[0]`,
`for x in range(n)`; `push(массив, значение)` добавляет в конец.

## Сценарий целиком

Пример узла из `projects/oborona/scripts/duck.og`:

```og
var hp = 100
var row = 0
var dead = false

func _process(dt):
    if dead:
        return
    var g = get_node("/Root")
    var p = g.plant_in_front(row, self.x + 15)
    if p != null:
        p.hp = p.hp - 50 * dt
        return
    self.x = self.x - 30 * dt
    if self.x < 235:
        g.duck_reached_home(self)

func hurt(d):
    hp -= d
    if hp <= 0:
        dead = true
        get_node("/Root").duck_died(self)
        self.free()
```

## Детерминированность и повтор ввода

Один и тот же проект, `seed` и файл повтора ввода всегда дают один и тот
же результат — поэтому движок применим к автотестам: `demo_test` отыгрывает
матч «Обороны грядки» целиком (автопилот на ОгScript) и требует победы.
Реплей ввода:

```
1 press 70 435     # зажать карточку подсолнуха
4 move 400 480     # тянуть
8 release 649 512  # отпустить на клетке
```

## Тесты

* `vm_test` — 58 проверок языка: арифметика, строки, циклы, рекурсия,
  массивы, глобальные переменные, ошибки с номерами строк, деление на ноль.
* `engine_test` — 38 проверок движка: узлы, свойства, ввод и захват,
  `spawn`/`free`, сцены и файлы проекта, рендер кадра.
* `demo_test` — сквозные прогоны обеих демо-игр: «Оборона грядки»
  выигрывается автопилотом, посадка перетаскиванием карточки работает,
  «Кирпичи» выигрываются за ~63 секунды.
* `android_host_test` — Android-хост из APK на заглушках
  `engine/tests/android_fake*`: окно 1280×720, кадры меню, касание
  запускает нужную игру, обе игры читаются из встроенных в библиотеку
  файлов (тест делает `chdir("/")`), ошибок в логе нет.

Все четыре собираются с `-Wall -Wextra -Werror` и проходят без утечек под
AddressSanitizer/UndefinedBehaviorSanitizer.

## Android: APK и виртуальная файловая система

`engine/android/og_android.c` — хост движка на Android: `NativeActivity`,
EGL/GLES2, программный кадр движка загружается в одну текстуру
`GL_TEXTURE_2D`, окно 800×600 вписывается в альбомный экран, касание
пересчитывается в координаты проекта. Java-кода нет вообще.

```sh
python3 tools/pack_project.py --check   # проекты совпадают с заголовком
python3 tools/pack_project.py           # переупаковать projects/ в .h
engine/android/build_apk.sh             # подписанный OboronOgorod.apk
```

* `tools/pack_project.py` кладёт `projects/oborona` и `projects/kirpichi`
  (16 файлов: `.og`, `.scene`, `.cfg`, `.txt`) в
  `engine/android/og_project_data.h` — детерминированно, без зависимостей.
* `engine/og_vfs.c` (`og_read_file`) сначала ищет файл во встроенной
  таблице, потом на диске: в APK игра читается из библиотеки, а на ПК
  движок по-прежнему работает с папкой проекта.
* `engine/android/AndroidManifest.xml` — пакет `app.ogorod`,
  `hasCode="false"`, ландшафт, minSdk 29 / targetSdk 34.
* `engine/android/build_apk.sh` — clang NDK под обе ABI, aapt, zipalign,
  подпись тестовым ключом; нужны `ANDROID_HOME` (platforms/android-34) и
  `ANDROID_NDK_ROOT`.
* Тест хоста собирается обычным `cc` с `-Itests/android_fake`:
  `make -C engine android_host_test` — тот же `og_android.c`, что попадает
  в `libogorod.so`, но с заглушками вместо Android.

## Игры

**`projects/oborona`** — башенная оборона в духе исходного боя: 5 рядов
по 9 клеток, утки-противники, горохострелы, орехи, подсолнухи с монетами
и газонокосилки. Логика целиком в `scripts/*.og`; `game.og` отвечает за
правила, остальные скрипты — за узлы (утка, горошина, растение, монета,
косилка, карточка). Игрок сажает растения перетаскиванием карточки, но по
умолчанию включён автопилот — чтобы матч можно было проверить в CI.

**`projects/kirpichi`** — арканоид: мяч, планка, кирпичи с прочностью,
жизни и очки. Планка едет за мячом сама, пока игрок не схватит её мышью.
