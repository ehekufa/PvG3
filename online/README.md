## Два игрока

1. Создатель выбирает карту и создаёт короткий код комнаты через «+».
2. Друг открывает ссылку/код или выбирает свободную комнату из списка.
3. Оба выбирают разные стороны: растения Кирилла или утки-зомби.
4. Создатель комнаты считает физику и публикует снимки поля в
   `/rooms/{код}/state`; гость пишет по одной команде в
   `/rooms/{код}/command`, дожидаясь подтверждения `ackGuest`.
5. Обычная утка, утка с конусом и утка с ведром используют три отдельные
   авторские иллюстрации (180 / 420 / 750 HP). Водная карта требует кувшинок.

Стороны не могут быть выбраны одинаково. Создатель — авторитетный игрок:
если он закроет страницу или отключится, матч не продолжится. Возвращение
на страницу в той же вкладке восстанавливает роль и последний снимок.
Комнаты удаляются при явном выходе; старые комнаты старше 10 минут
скрываются из списка. Кампания Android никогда не отправляется в Firebase.

## Мастерская и каталог уровней игроков

В браузерном онлайн-разделе есть отдельная **«Мастерская платформера»**:
черновик автоматически сохраняется в IndexedDB; для небольших черновиков остаётся
резервная копия в localStorage. На уровень разрешено до 20 000 объектов суммарно
(блоки, триггеры, монеты и прочие типы). Редактор строит сцену 16×10,
а предпросмотр поддерживает клавиатуру и экранные кнопки **«Назад» / «Вперёд»**,
«Прыжок» и «Действие». В редакторе отдельные зелёные стрелки сдвигают выделенные
объекты на полблока (шаг можно изменить), бирюзовые — окно карты; можно также
перетаскивать карту в режиме «Карта». Кнопки «Зеркало» отражают выделение
слева направо или сверху вниз, независимо от поворота. Закруглённые стрелки
поворачивают выделение на ±45°, а поле угла задаёт точное
значение без изменения триггеров. Триггер «Разворот» вращает объекты выбранной группы
по одному обороту в секунду в течение заданного времени (1–9999 секунд). Событие
может срабатывать от касания, подбора монеты, кнопки действия или старта уровня.
Триггер «Гравитация» задаёт силу уровня ползунком от −100 (слабее) до +100
(сильнее), независимо от группы объектов. Есть также триггеры «Невидимость»
(скрыть изображение группы, сохранив столкновения) и «Нет столкновения»
(пройти сквозь объекты группы); повернутые блоки в проверке уровня используют
фактическую форму коллизии. Хитбоксы персонажа, врагов, монет и финиша
не включают прозрачные поля PNG; шип и склон используют треугольные контуры.
Категория «Блоки» объединяет обычный блок,
безопасный треугольный «Склон» (использует рисунок `Склон.png`; по нему можно
подниматься без урона) и платформу. Форму выбирают внутри категории — как
вариант триггера. Орбы — отдельные игровые объекты, не триггеры; доступны
жёлтый и оранжевый варианты. У орбов нет твёрдого тела: простое касание или
пролёт насквозь не подбрасывает игрока. Нажми «Прыжок» либо кликни/тапни по
игровому полю один раз, пока игрок находится в круглой зоне активации орба;
жёлтый даёт стандартный импульс вверх, оранжевый — более сильный. Орбы не
меняют гравитацию. Орбы периодически искрятся. Категория **P / Частицы**
добавляет эмиттер, который не имеет коллизии и показывается в редакторе буквой P.
Для выбранного P открой **«Настроить эмиттер»**: можно включить/выключить поток,
выбрать непрерывный режим или всплески, задать скорость, направление, разброс,
время жизни, размер, гравитацию и свечение. Чёрный квадрат показывает живой
предпросмотр с точкой рождения P. Настройки сохраняются в опубликованном уровне;
для старых записей без настроек применяются значения по умолчанию. Сам маркер P
в игре скрыт, а частицы видны.
Все триггеры видны только в редакторе и скрыты в игровом предпросмотре. На телефоне кнопки принимают одновременные касания (например, движение и прыжок);
графические стрелки рисуются CSS-геометрией.
Платформы, блоки, склон, шипы, триггеры, оба орба и финиш используют
PNG-рисунки; в нативной C-версии они встроены в спрайты. Для игрока, гуся и монет используются
существующие иллюстрации игры. Пользователь сам нажимает **«Опубликовать»**
после проверки уровня. Запись формата
`PVG3-PUBLISHED-LEVEL` появляется в общем `/levels/{id}` и её краткая карточка —
в `/levels-index/{id}`; веб-каталог запускает те же опубликованные уровни.

Нативные клиенты Android и Windows читают `/levels-index`, показывают ID и
название, а выбранную запись `/levels/{id}` запускают в C-runtime. Android принимает
каждый палец отдельно: кнопки движения и прыжка работают одновременно. Векторные
стрелки нативного управления строятся из прямоугольников и треугольников LVGL,
без картинок. Текущий формат каталога, опубликованные уровни и C-runtime сохранены.

Для чтения каталога правила RTDB должны разрешать чтение `/levels-index` и
`/levels`. Публикации дополнительно нужна запись в обе ветки. Веб-клиент
создаёт случайный ID и использует условную запись `If-Match: null_etag`, чтобы
случайно не перезаписать существующий уровень. Это **не защита от злоумышленника**:
открытая публичная запись позволяет любому менять или удалять данные. Если
правила запрещают запись, сайт оставит черновик локально и покажет понятную
ошибку; правила автоматически не меняются. Для настоящей публичной публикации
предпочтительнее Firebase Anonymous Auth и серверная валидация.

Пример демонстрационных (небезопасных) правил — добавляй только нужные ветки
к действующему `rules`, не заменяя другие правила и не удаляя опубликованные
данные:

```json
{
  "rules": {
    "levels": { ".read": true, ".write": true },
    "levels-index": { ".read": true, ".write": true }
  }
}
```

До явного решения владельца Firebase эти правила не применяются и настоящая
база не используется для тестовых записей. Тесты публикации работают только
с поддельным Firebase REST.

## Доступ Firebase

URL базы: <https://pvg3-ae824-default-rtdb.firebaseio.com/>.
27.09.2026 одноразовая проверка на GitHub Actions успешно выполнила GET,
браузерный CORS OPTIONS, условный PUT, GET созданного узла и DELETE: база
на момент проверки разрешала создание комнат. Если права позже изменятся,
игра покажет ошибку. Сайт не содержит API-ключа, пароля или закрытого токена. Если создание
комнаты возвращает `Permission denied`, владелец Firebase может добавить
в **существующие** правила на время тестов доступ только к узлу `rooms`:

```json
{
  "rules": {
    "rooms": {
      ".read": true,
      ".write": true
    }
  }
}
```

**Не заменяй существующие правила проекта этим фрагментом целиком** —
вставь `rooms` под действующий `rules`, сохранив правила других веток.
Публичная запись небезопасна: любой может изменить или удалить комнату.
Это демонстрационный режим без учётных записей, рейтинга и античита.
Для публичного сервера нужны Firebase Anonymous Auth, проверка ролей в
правилах и защита запросов от злоупотреблений. Не храни личные данные
в комнате.

## Тесты и локальный просмотр

```sh
node --test online/test/*.test.js
python3 -m http.server 8000 --bind 0.0.0.0
```

Открой `/online/` на том же сервере. Тесты используют фальшивый Firebase
REST и **не пишут** в настоящую базу. Игра написана на обычных JavaScript,
HTML и CSS, без npm-зависимостей.
