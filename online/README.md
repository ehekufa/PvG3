Браузерная арена адаптируется для телефона и компьютера; игровое поле остаётся
16:9, а панели на узком экране складываются в одну колонку.
Firebase хранит комнаты и ходы браузерной арены, а также опубликованные
платформерные уровни и каталог для нативной C-игры.

## Два игрока

1. Создатель выбирает карту и создаёт короткий код комнаты через «+».
2. Друг открывает ссылку/код или выбирает свободную комнату из списка.
3. Оба выбирают разные стороны: растения Кирилла или утки-зомби.
4. Создатель комнаты считает физику и публикует снимки поля в
   `/rooms/{код}/state`; гость пишет по одной команде в
   `/rooms/{код}/command`, дожидаясь подтверждения `ackGuest`.
5. Обычная утка, утка с конусом и утка с ведром используют три отдельные
   авторские иллюстрации (180 / 420 / 750 HP). Водная карта требует кувшинок.

Стороны не могут быть выбраны одинаково. Создатель — авторитетный игрок:
если он закроет страницу или отключится, матч не продолжится. Возвращение
на страницу в той же вкладке восстанавливает роль и последний снимок.
Комнаты удаляются при явном выходе; старые комнаты старше 10 минут
скрываются из списка. Кампания Android никогда не отправляется в Firebase.

## Каталог уровней игроков

В Android-игре раздел **«Уровни игроков»** читает `/levels-index`, показывает ID
и название, а выбранную запись `/levels/{id}` запускает в нативном C-runtime.
Поддержка джойстика, прыжка и триггеров в runtime сохранена. Уже опубликованные
уровни и совместимый с ними формат `PVG3-MAKER` оставлены без изменений.

Браузерная мастерская и публикационный интерфейс удалены. Поэтому репозиторий
больше не создаёт и не публикует новые записи, а существующий каталог не
удаляется и остаётся доступен для чтения из игры. Для него Firebase RTDB должна
разрешать чтение `/levels-index` и `/levels`; публичная запись не нужна.
Не удаляй эти ветки или уже опубликованные данные при обновлении правил.

## Доступ Firebase

URL базы: <https://pvg3-ae824-default-rtdb.firebaseio.com/>.
27.09.2026 одноразовая проверка на GitHub Actions успешно выполнила GET,
браузерный CORS OPTIONS, условный PUT, GET созданного узла и DELETE: база
на момент проверки разрешала создание комнат. Если права позже изменятся,
игра покажет ошибку. Сайт не содержит API-ключа, пароля или закрытого токена. Если создание
комнаты возвращает `Permission denied`, владелец Firebase может добавить
в **существующие** правила на время тестов доступ только к узлу `rooms`:

```json
{
  "rules": {
    "rooms": {
      ".read": true,
      ".write": true
    }
  }
}
```

**Не заменяй существующие правила проекта этим фрагментом целиком** —
вставь `rooms` под действующий `rules`, сохранив правила других веток.
Публичная запись небезопасна: любой может изменить или удалить комнату.
Это демонстрационный режим без учётных записей, рейтинга и античита.
Для публичного сервера нужны Firebase Anonymous Auth, проверка ролей в
правилах и защита запросов от злоупотреблений. Не храни личные данные
в комнате.

## Тесты и локальный просмотр

```sh
node --test online/test/*.test.js
python3 -m http.server 8000 --bind 0.0.0.0
```

Открой `/online/` на том же сервере. Тесты используют фальшивый Firebase
REST и **не пишут** в настоящую базу. Игра написана на обычных JavaScript,
HTML и CSS, без npm-зависимостей.
