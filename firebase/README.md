# Правила базы и аккаунты PvG3

Здесь лежит всё, что относится к Firebase Realtime Database: правила доступа,
устройство аккаунтов, комментариев и банов, и как спрятать адрес базы и секрет
сборки из исходников.

## Файлы

| Файл | Что это |
| --- | --- |
| `firebase/database.rules.json` | Правила базы. Единственное место, где описано, кто и что может писать. |
| `tools/firebase-admin.mjs` | Утилита: публикует правила, назначает модераторов, банит, считает аккаунты. Секрет читает из переменных окружения. |
| `src/online_config.h` + `src/online_config_secret.h.example` | Адрес базы и необязательный токен для нативной игры (APK/EXE). |
| `online/firebase-config.js` + `online/firebase-secret.example.js` | То же самое для браузерной мастерской. |

## Как залить правила

**Способ 1, консоль.** Firebase console → Realtime Database → Rules → вставить
содержимое `database.rules.json` → Publish.

**Способ 2, из терминала** (секрет никуда не сохраняется, только в переменные
окружения):

```sh
export PVG3_DATABASE_HOST='<адрес базы>'
export PVG3_DATABASE_SECRET='…'   # Настройки проекта → Service accounts → Database secrets
node tools/firebase-admin.mjs rules
node tools/firebase-admin.mjs show-rules   # проверить, что залилось
```

Пока правила не залиты, база остаётся в том режиме, что был раньше: аккаунты,
комментарии и баны не защищены.

## Что лежит в базе

| Ветка | Кто читает | Кто пишет |
| --- | --- | --- |
| `/rooms/{код}` | все | все (онлайн-матч, как раньше) |
| `/levels/{id}` | все | создать или изменить свой уровень может только его автор с действующим токеном; чужой — только модератор; `official: true` — только модератор; забаненный автор — никто; удаление запрещено |
| `/levels-index/{id}` | все | только действующий автор уровня (токен сверяется с записью `/levels/{id}`); удаление запрещено |
| `/level-stats/{id}/likes/{install-id}` | все | анонимная установка создаёт `true` один раз; удалить свой лайк можно переключателем |
| `/level-stats/{id}/downloads/{install-id}` | все | одна запись на уровень и установку; повторная загрузка не увеличивает счётчик |
| `/comments/{уровень}/{id}` | все | автор сообщения; скрыть (`hidden: true`) — автор сообщения или модератор, при этом текст и автор сообщения остаются прежними |
| `/accounts/{ник}` | **никто** | создать новый ник может кто угодно (если он свободен); менять — только зная действующий токен |
| `/tokens/{ник}` | **никто** | тот, кто знает хэш пароля (это и есть вход); забаненный ник токен не получит |
| `/admins/{ник}` | все | **никто из клиентов** — только консоль или секрет базы |
| `/bans/{ник}` | все | только модератор |

Удалять из `/accounts`, `/comments`, `/bans` правила не дают: вместо удаления
ставятся `hidden: true` и `banned: false`, поэтому история модерации сохраняется.

## Аккаунты

* **Ник** — только латинские буквы `a–z`, цифры `0–9` и `_`, от 3 до 24 знаков.
  Пробелы, `@`, `₽`, `?`, `!`, `:`, `¢`, `°`, `√`, `™`, `§`, `£`, `€`, кириллица
  и эмодзи запрещены правилами базы, а не только формой на сайте. Регистр и
  пробелы по краям сводятся к одному виду, поэтому `Qwerty`, ` qwerty ` и
  `qwerty` — один и тот же аккаунт, а двух одинаковых создать нельзя: занятый ник
  база просто не даст записать.
* **Пароль** — от 6 до 72 знаков, без пробелов. Сам пароль с устройства не
  уходит: клиент считает `PBKDF2-SHA256` (150 000 раундов, соль выводится из
  ника) и отправляет только 64 шестнадцатеричных знака хэша.
* **Вход** — обмен хэша на случайный токен сессии в `/tokens/{ник}`. Неверный
  пароль или несуществующий ник дают один и тот же ответ: «Неверный ник или
  пароль». Каждый вход выпускает новый токен, старый перестаёт работать.
* Прочитать `/accounts` и `/tokens` нельзя никому, так что ни хэши, ни токены не
  публикуются.
* Для публикации запись уровня и её карточка каталога должны подтвердить
  совпадающий действующий токен автора. Токен на короткое время попадает в
  публичное поле `author.tok`, поэтому клиент сразу после публикации и после
  каждого действия модератора выпускает новый токен: старый больше не подходит.
* Гостю интерфейсы не отправляют запрос публикации: открывают окно входа или
  регистрации и автоматически продолжают публикацию после успешной авторизации.
  Те же требования повторно проверяет Firebase Rules.

## Модератор

Модератор — это просто ник в `/admins`. Добавить его может только консоль или
секрет базы, из игры и с сайта ветка не пишется. Для этой базы владелец вручную
добавляет в Firebase Console запись `/admins/qwertyuiopaj1234 = true`; проект
не назначает модератора автоматически.

Для других ручных административных операций предусмотрена CLI-утилита:

```sh
node tools/firebase-admin.mjs admin <ник>
node tools/firebase-admin.mjs list-admins
```

Модератор может:

* сделать уровень **официальным** (в каталоге появляется жёлтый бейдж
  «ОФИЦИАЛЬНЫЙ») и снять этот статус;
* **забанить** ника — за плохие сообщения, непроходимый уровень и так далее;
  забаненный не публикует уровни и не пишет сообщения (этим занимаются правила,
  а не только форма);
* **скрыть** любое сообщение под уровнем (текст и автор при этом не меняются,
  только появляется `hidden: true`).

Игрок может скрыть только своё сообщение.

## Сообщения под уровнями

Комментарии живут в отдельной ветке `/comments/{id уровня}/{id сообщения}` — сам
запись уровня они не портят, поэтому старые клиенты по-прежнему читают уровни.
Ограничения: до 300 знаков, не чаще одного сообщения на отправку, писать могут
только игроки с аккаунтом. Сообщения забаненных ников скрываются и на клиенте,
и правилами.

## Аккаунты в игре (APK/EXE)

Нативная игра работает с той же базой и теми же ветками, что и браузерная
мастерская, и считает хэш ровно так же, как `online/` (проверено одними и теми
же контрольными векторами: `tools/native_account_test.c`). Поэтому аккаунт,
созданный на сайте, открывается в игре, и наоборот.

* Кнопка **«Аккаунт»** доступна прямо в каталоге «Уровни игроков», в мастерской
  и в редакторе. Поля «Ник» и «Пароль» заполняются экранной клавиатурой,
  **«Создать аккаунт»** регистрирует (занятый ник → «Такой аккаунт уже есть.»),
  **«Войти»** входит. Если гость нажимает **«Публиковать»**, игра показывает
  окно входа/регистрации и продолжает публикацию после успеха. Проверки ника
  и пароля те же, что на сайте: `a–z`, `0–9`, `_`, 3–24 знака, пароль 6–72 без
  пробелов. Неправильный ник или пароль дают один ответ: «Неверный ник или
  пароль».
* Сессия (ник, токен, хэш, флаг модератора) хранится в файле настроек рядом с
  сохранением (`PVG3-PREFERENCES 3`) и подхватывается при следующем запуске;
  **«Выйти»** её стирает и на устройстве, и в памяти.
* Выделенная карточка уровня даёт кнопки **«Играть»**, **«Сообщения»** и —
  только модератору — **«Официальный»**/**«Снять метку»**. Бейдж пишется в
  `/levels/{id}/official` и `/levels-index/{id}/official`, сам уровень заново
  не заливается, жёлтая метка «ОФИЦИАЛЬНЫЙ» видна и в игре, и на сайте.
* Окно сообщений показывает до 4 сообщений, поле ввода и кнопку «Отправить»;
  своё сообщение игрок может **«Скрыть»**, модератор — скрыть любое и
  **«Забанить»** автора прямо из строки сообщения (причина «Плохое сообщение»).
  Забанить ника можно и в окне аккаунта (причина «Нарушение правил»).
* После публикации уровня, бана, скрытия сообщения и постановки метки игра
  сразу выпускает новый токен: старый на несколько секунд попадал в публичную
  запись, дальше он не работает.

Модератора в игре нельзя назначить самому — `/admins` пишется только из
консоли или утилитой `tools/firebase-admin.mjs admin <ник>`.

## Как спрятать адрес базы и секреты сборки

Адрес, который лежит в git, **закодирован**: это hex от «каждый байт адреса XOR
ключ» (`PVG3_DATABASE_HOST_ENC` + `PVG3_DATABASE_HOST_KEY` в
`src/online_config.h` и `ENCODED_HOST` + `HOST_KEY` в
`online/firebase-config.js`). Клиент раскодирует его при старте. Честно: ключ
лежит рядом со значением, поэтому это **скрытие, а не настоящее шифрование** —
тот, кто разберёт APK или откроет скрипт, адрес получит. Настоящая защита —
адрес вообще не попадает в git, а приходит на сборку:

1. Свой адрес (и, если нужен, токен `?auth=`) задайте либо локально

   ```sh
   PVG3_DATABASE_HOST='<ваш адрес>' PVG3_DATABASE_AUTH='' sh tools/write_online_config.sh
   ```

   — скрипт запишет `src/online_config_secret.h` и `online/firebase-secret.js`
   (оба в `.gitignore`), либо в GitHub: Settings → Secrets and variables →
   Actions → New repository secret: `PVG3_DATABASE_HOST` и
   `PVG3_DATABASE_AUTH`. Оба пайплайна вызывают тот же скрипт перед сборкой;
   если секретов нет, берётся закодированное значение по умолчанию.
2. Скопировать примеры вручную тоже можно:
   `src/online_config_secret.h.example` → `src/online_config_secret.h`,
   `online/firebase-secret.example.js` → `online/firebase-secret.js`.
3. Перекодировать адрес по-своему:
   `sh tools/write_online_config.sh --encode <адрес> <ключ>` — выведет пару
   «key/hex», которую нужно вставить в оба файла конфигурации.

Сами секреты (`PVG3_DATABASE_SECRET`, `PVG3_KEYSTORE_BASE64`, …) в репозитории
не хранятся, в артефакты не попадают и в чаты не уходят: их вводите только вы.
`tools/firebase-admin.mjs` читает их из переменных окружения и не имеет
значений по умолчанию.

## Честные ограничения

Своего сервера у проекта нет: всё, что разрешают правила, клиент делает сам.
Поэтому:

* токен модератора виден внутри записи бана или скрытого сообщения — после
  каждого такого действия клиент сразу выпускает новый токен, так что
  подсмотренный перестаёт работать при следующем входе;
* пароль подбирается офлайн, если кто-то доберётся до хэша, — поэтому пароль
  должен быть своим и длинным, а адрес базы и `/accounts` закрыты для чтения;
* токен автора кратко виден в публичном поле `author.tok` записи уровня, но
  после завершения публикации или модераторского действия сразу заменяется;
  старый токен становится недействительным. Если в Firebase всё ещё загружены
  старые демонстрационные правила с `.write: true`, интерфейсный запрет можно
  обойти прямым запросом — опубликуйте `firebase/database.rules.json`.
